# 真实案例问题记录与优化闭环

该文档只记录真实运行中观察到的问题，以及对平台行为的实际修改。它不是把所有潜在风险重新列成计划。

## RC-001：经纬度 COG 的目标分辨率单位错误（已修复）

- **首次证据**：真实 WorldCover COG 使用 `target_resolution=10` 下载后，资产元数据显示输出为 `1 × 1`、EPSG:4326。
- **根因**：旧实现使用 `pixel_width / target_resolution`，没有考虑 EPSG:4326 的 transform 单位是度；10 米被当成 10 度。
- **影响**：参考栅格被压缩，任何指标都不可信；第一次运行结果被判定为无效，没有作为科学结果使用。
- **修改**：`ResearchStacService._prepare_geotiff_dataset` 对地理 CRS 按窗口纬度将经纬度范围转换为米；投影 CRS 使用线性单位因子；metadata 明确记录米制解释。
- **回归测试**：`test_geographic_target_resolution_is_interpreted_as_metres`。
- **修复后证据**：WorldCover 裁剪输出 `974 × 1106`；对齐到 Sentinel 网格后为 `755 × 1116`，并完成正式 PythonRunner 运行。

## RC-002：大 COG 无法计算完整源文件 SHA-256（已按边界记录）

- **证据**：WorldCover 源对象约 `114,368,904` 字节，超过本地整文件下载上限；服务使用 HTTP Range 只读取 bbox 窗口。
- **影响**：系统不能把未完整读取的远端源对象伪装成已经计算过完整 SHA-256。
- **当前处理**：资产记录 `source_hash_scope=stored_output_only`，并保留 `output_sha256`、STAC item、asset href、裁剪 bbox 和处理元数据。
- **剩余风险**：如果需要证明远端对象的完整内容不可变，应另行保存提供方的对象版本/ETag 或在许可和资源允许时完成整对象下载。

## RC-003：WorldCover 2021 与 Sentinel-2 2024 不同期（未作为真值，已限制结论）

- **证据**：本案例场景日期为 2024-10-05，参考产品为 ESA WorldCover 2021。
- **影响**：参考层可能无法表达 2024 同期水体边界；这不是严格的同期独立标签。
- **当前处理**：项目协议、EvidenceCard、研究报告和本案例文档都把它标为 `proxy`，结论边界禁止写成现场精度或湖泊泛化结论。
- **后续优化**：引入同期人工判读样本、水文站/外业数据或经过审查的同期权威产品；正式实验按时间层和空间块冻结独立样本。

## RC-004：像元级 Wilson 区间不能代表空间抽样不确定性（未伪造，已限制结论）

- **证据**：本次有效像元数达到 `842,580`，普通未加权 Wilson 区间很窄，但像元存在强空间相关。
- **影响**：若把该区间写成复杂抽样或地图面积误差，会夸大确定性。
- **当前处理**：manifest 和报告明确记录 `wilson_95_unweighted` 及其独立性假设；没有把它包装成设计一致区间。
- **后续优化**：使用预先声明的空间/时间分层样本、抽样权重和设计一致的方差估计；必要时同时报告 block bootstrap 或其他空间相关方法。

## RC-005：单个低云场景和单个小 ROI 不能证明泛化（未作为结论，待扩展）

- **证据**：案例选择了 STAC 返回的低云量场景，并只裁剪了 `0.10° × 0.10°` 范围。
- **影响**：结果可能受到场景选择、季节和局地水陆结构影响。
- **当前处理**：研究报告明确禁止湖面级、季节级和方法优越性结论。
- **后续优化**：冻结多个时间层、多个空间 block 和统一的数据选择规则；在模型选择和独立测试之间禁止泄漏。

## RC-006：Sentinel-1 GRD 裁剪路径缺少可用 CRS（已绕开并保留限制）

- **首次证据**：Planetary Computer `sentinel-1-grd` 的 VV COG 在指定 `crop_bbox` 下载时返回“STAC GeoTIFF 必须包含 CRS”。
- **影响**：不能把该候选未经确认地裁剪或登记为可运行输入；继续运行会把空间参考问题隐藏在结果中。
- **当前处理**：案例切换到同一数据服务提供的 `sentinel-1-rtc` VV asset，并在摘要中保留集合选择；GRD 失败不被当成成功结果。
- **后续优化**：在 STAC 下载器中对缺少 CRS 的资产提前做元数据诊断，提供不裁剪的安全失败信息；若用户明确提供 CRS 才允许后续处理。

## RC-007：SAR 原始单位与阈值单位不一致（已修复）

- **首次证据**：RTC VV 输出统计范围约为 `0.002–466`，明显是线性功率；直接应用 `-17 dB` 阈值的试跑预测水体像元为 `0`。
- **影响**：流程状态可以是 `completed`，但科学语义错误，属于必须拒绝的“形式成功”。
- **修改**：脚本在重投影后的派生资产上显式执行 `VV_dB = 10*log10(VV_linear)`，资产名、FormulaSpec 说明和本案例文档均记录单位转换；随后以 `-17 dB` 重跑。
- **修复后证据**：SAR 预测水体像元 `32,302`，Recall `0.276985`、F1 `0.408235`；该结果仍只是 WorldCover 代理对照，不能外推为 SAR 物理精度。

## RC-008：派生资产类型与执行器输入契约不一致（已修复）

- **首次证据**：显式对齐后的 VV GeoTIFF 首次登记为 `derived`，但 PythonRunner 的公式输入契约只接受快照中的 `raster`，SAR 运行被正确拒绝。
- **影响**：研究者会看到“文件存在但公式不能运行”的不透明失败。
- **修改**：保留“derived operation”在文件名/快照关系中，同时将可执行 GeoTIFF 登记为 `raster`；快照同时包含原始 RTC 和对齐后的输入，保证来源可追溯；上传接口新增受限 `metadata_json` provenance，记录转换公式、单位、重采样和目标网格。
- **回归结果**：光学与 SAR formal Run 均 `completed`，两份 evidence package 均 `verified=true`，formal comparison `comparable=true`。
